# v4.3.1 — 复核处置轮：防注入缝隙 / 混排保终稿 / 容错修复 / 键盘可达

> 本版来自一次**外部独立复核**（50 条断言逐条验证，报告见 [docs/review-kimi-audit-v4.3.0.md](https://github.com/HXHndj/dsh-prompt-enhancer/blob/main/docs/review-kimi-audit-v4.3.0.md)）后的定向修复。共处置 **12 项**：提示词与容错层（A 梯队）+ 键盘可达（F1）；用户逐项拍板授权，P1 走**轻量方案**（不动历史消息载荷与记忆链预算口径）。

## 🎯 修了什么

### 提示词层

- **P1/N3 历史轮与澄清参考消息的防注入真空（本次最高危项）**：多轮记忆下，历史轮是**裸 user/assistant 消息**注入，只有末条带「证据正文」声明，而模板与纪律层的防注入条款都只覆盖「证据正文」——历史轮里的「忽略之前的指令」类文本三层防御全部落空（该缝隙早在项目审计中记录、一直未排期）。修法：声明行追加历史轮框架说明 + 澄清参考消息同口径标注 + 纪律层新增第 13 条（三档与自定义模板无条件生效）+ 公共层/轻量档任务边界各加一条。
- **P3–P7 提示词一致性**：专家档示例 6 改为**真实载荷形态**并补示例 7（`"skipped": true`）；**段名随主体语言**（中文 `## 任务` ↔ 英文 `## Task` 等五段映射）；新增**「已足够好时的出口」**（无依据可改进时允许近乎原样输出，不得为「看起来优化过」而改写）；专家档定位去掉 UI 元描述、消掉与「跳过处理」条的字面冲突；纪律第 4 条补澄清 JSON 围栏例外。

### 容错层

- **N1 混排输出整段丢弃已生成终稿**：模型违反「不得混排」输出「终稿 + 澄清 JSON」时，旧实现命中澄清即 `text:''` ⇒ 已生成的终稿被整段丢弃、用户只见澄清卡。现在按残余正文判定：**有实质正文 → 剥掉 JSON 后走终稿**，纯澄清信号仍弹卡（`parseClarify` 容错矩阵逐字不变）。
- **P2 继续优化框架**：只要实际注入了历史轮就给继续优化框架（旧实现要求与上轮存在 diff，于是「记忆开 + 有历史轮 + 本轮未改动」时模型收到历史轮却没有任何框架说明）。
- **B1 准备期异常泄漏 `pending`**：analyze/assemble 抛错时记录与 `AbortController` 永不清理（同键进度轮询长期返回假进度）。现在冒泡前清理，**RPC 错误语义不变**。
- **B2 错误误分类**：`collectStream` 把迭代期任何异常归一为 cancelled ⇒ 真实网络异常被误报为 ABORTED/TIMEOUT **且整请求中断**、丢掉原始错误码。现在只有全局取消/超时才判 cancelled，其余保留原始码并回到「换链 → 整链重试」的既有容错。
- **N2 看门狗真掐 signal**：旧实现只调 `iterator.return()`（对阻塞在 `await next()` 的流只是排队），与同文件自述「signal 才是唯一真掐断通道」矛盾。现在每次尝试独立 `AbortController` + `AbortSignal.any` 组合，看门狗触发即真中断在途请求；探测/换链语义不变。

### 界面

- **F1 键盘可达**：✨ 主键（三态）与 ▾ 触发器进入 Tab 序列（禁用态仍退出），新增 `brand-primary` 焦点环；副键保持「仅点击」。修复前键盘用户**完全无法**从输入框触发优化。

## ⚠️ 升级注意

- **必须完整重启 DSH**（不是刷新页面）：宿主半部 `plugin-host.js` 在进程启动时一次性加载。只更新文件不重启会出现「新 UI + 旧宿主」的假阴性。
- **本版不改动消息载荷与记忆链预算口径**（P1 轻量方案），历史记忆链行为与 v4.3.0 一致。
- 本轮**未包含**：F2 设置页下拉键盘导航、错误条重试按钮、优化历史视图、多标签 seq 隔离等（仍在册，见复核报告 §9.2）——**键盘无障碍目前是半截的**（主键可用、设置页下拉仍不可用）。

## ✅ 本次实测

- **测试与门禁**：`npm test` **328/328 通过**（基线 321，新增 7 条：`collectStream` 异常分类、U70 混排剥离边界 20 项、SMK-V431-01~04、V431-F1）；`npm run gate` **30 通过 / 0 冲突**；`build-host --check` / `build-client --check` / `sync-prompts --check` 三处一致。
- **混排保终稿**：产物级 mock llm 驱动——「长终稿 + 澄清 JSON」⇒ 返回终稿且不含 JSON/围栏；纯澄清 ⇒ 仍 `text:''` + 澄清卡。
- **pending 泄漏**：hostile getter 触发 analyze 抛错 ⇒ handler 拒绝，同键进度轮询返回 `NO_RECORD`（旧实现长期返回假进度）。
- **看门狗掐 signal**：看门狗窗口触发后，本次尝试的 `signal.aborted === true`，且仍完成「探测 → 换链」。

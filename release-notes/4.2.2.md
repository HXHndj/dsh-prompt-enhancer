# v4.2.2 — 副键布局重排（28×28 圆形·两态选中范围一致）+「继续优化」蓝色态 / 「重新优化」同形中性底

> 纯客户端呈现层修正：修掉你截图指出的两处观感缺陷——**「撤销优化 / 重新优化」两枚副键的选中范围不一致、居中对齐没做好**；并按拍板把**「继续优化」改为蓝字 + 浅蓝底**（与「撤销优化」同一配方）、**「重新优化」补同形中性底**。RPC 面 24 条不变、配置 schema 与记忆链结构零改动、**无行为变更**。

## 🎨 界面（输入框工具行）

- **副键固定 28×28 圆形（预设 A）**：旧实现 `.dsh-enh-aux{min-width:20px;padding:0 4px}` 令**盒宽随内容变化**——⟳ 是字体字形（advance≈12px）⇒ 盒宽 **20px**、↩ 是 14×14 内联 SVG ⇒ 盒宽 **22px**，两态「选中范围」相差 2px、图标中心到主键文字的墨迹距离随之差 1px（**「选中范围不一致 + 居中对齐没做好」的根因**）。现固定 `width/min-width/height:28px` + `padding:0`，盒宽与内容彻底解耦 ⇒ **两态选中范围恒为同一枚 28×28 圆**。
- **`margin-right` 由 `-2px` 改 `+2px`**：旧负值把副键盒压进主键盒 2px（两个高亮区粘连、副键 hover 被主键胶囊左端压住）；现留 2px 真实间隙，图标盒右缘 → 主键文字左缘 = 14px（6 + 2 + 6）。
- **图标容器固定 16×16 盒**：⟳ 字形（13px 行盒）与 ↩ SVG（14×14）此前盒高随内容浮动；现两态共用同一居中盒 ⇒ 图标在固定圆内恒居中（**图标几何零改动**：SVG 仍 14×14 / 1px 描边，字形仍 ⟳）。
- **`corner-shape:round`（关键）**：宿主全局注入 `*,:before,:after{corner-shape:var(--dsw-corner-shape)}`，`--dsw-corner-shape = superellipse(1.5)`（源码实测：`app.asar → @deepseek-ai/dsh-client-ui-theme/lib/client.js`）——大圆角会被超椭圆压成小圆角方块（**实机截图实测：声明的 24px 在 28px 高的主键上只渲染出 ≈8px 圆角**，副键 20px 宽更只剩 ≈5px）。副键因此显式声明 `corner-shape:round` 退出全局形状（**宿主自家 Pill/Switch 组件同款做法**），实机复查计算值为 `superellipse(1)`（= round）⇒ 真圆。
- **「继续优化」= 蓝字 + 浅蓝底**（需求 4）：新增 `.dsh-enh-btn-continue`，与「撤销优化」的 `.dsh-enh-btn-result` **逐字同构**——同一条 `color-mix(… 6%, transparent)` 配方，仅换色相。蓝取 `--dsw-alias-state-business-primary`（宿主自己的蓝色前景 token，`ui-conversation` 的 composer-editor 引用样式即用它；深色主题 = `deepseek-400 #7aaaff`、浅色主题 = `deepseek-500 #4176e6`，随主题自动切换）。**不用 `--dsw-alias-brand-primary`**——该 token 在本设计系统里是**中性色**（深色主题 = `neutral-bluish-50` 近白、浅色主题 = `neutral-bluish-1000` 近黑），不是蓝。
- **「重新优化」= 同形中性底**（选项 b）：新增 `.dsh-enh-btn-redo`（`label-secondary` 文字 + `label-secondary` 6% 淡底）⇒ 三个已优化态统一为「文字 + 淡底」形式；底色**刻意不用** `bg-layer-2/3`（深色主题下 `bg-layer-2` 正是工具行所在面板底色 `#2c2c2e`，会完全看不见），hover 仍走既有 `interactive-bg-hover` ⇒ 悬停仍有可见加深。

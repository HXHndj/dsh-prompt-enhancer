# v4.2.0 — 按钮双键状态机（从零重新优化 + 撤销放开）+ 小三角箭头方向切换动画

> 本轮把「优化成功之后」的按钮语义整理清楚：主键 + 左侧副键各司其职，新增**从零重新优化**入口，**撤销**不再只限「刚优化完」那一刻；同时修掉一个真实缺陷——记忆流开关切换后，主键与副键会**同时变成「撤销优化」**（⟳ 入口消失），且撤销会把草稿回退到**更旧的一轮**。全部改动**仅客户端**：RPC 面 24 条不变、配置 schema 零改动、记忆链数据结构不变。

## ✨ 按钮双键（主键 + 左侧副键）

| 状态 | 主键 | 左侧副键 |
| :-- | :-- | :-- |
| 首次（从未优化） | ✨ + 模式标签 | — |
| 优化成功、草稿未改 | **撤销优化** | **⟳ 从零重新优化** |
| 改动草稿 + 记忆流开（含专家档） | **继续优化**（带记忆上下文） | **↺ 撤销优化** |
| 改动草稿 + 记忆流关（轻量/标准） | **重新优化**（从零，本就没有上下文） | **↺ 撤销优化** |

- **从零重新优化 = 新开对话**：这一次请求**不带**记忆链、**不带**澄清记录（模型只看到当前草稿，从零读一遍），但**结果照常记入记忆链**——这样下一轮「继续优化」的修改基准不会错位（若不入链，模型会收到一个「你删掉了上一版内容」的假 diff，方向被带偏）。
- **撤销放开 + 连环回退**：改动草稿后副键就是撤销；撤一步回到那一轮的起点，链非空就能继续往回撤，撤到链空自动回「✨ 优化」首次态；撤销不写记忆链（维持既有 pop 语义）。
- 副键是纯图标小键（⟳/↺），悬停有提示（「从零重新优化：本次不带记忆上下文」/「撤销优化：恢复本轮优化前的草稿」）。

## 🎨 小三角箭头方向切换动画

- 输入框右侧的 **▾** 触发器：展开设置面板时箭头**平滑翻转朝上**，收起时翻回朝下；设置页下拉框箭头同源同动画（180ms ease）。
- 状态源直接用控件上既有的 `aria-expanded`——**没有新增任何状态或类名切换**；系统开启「减少动态效果」时自动关闭过渡（方向仍然切换，只是不做动画）。

## 🔧 修复

- **记忆流开关切换后主键/副键双双变成「撤销优化」**：开关切换**不**清记忆链，于是链尾可能是更旧的一轮，而「未改/已改」判定原先以链尾为基准 → 双 undo 窗口 + ⟳ 入口消失 + 撤销回退到更旧草稿。现改为**最近一次优化结果优先**（记忆流开时每轮都入链、两者恒等价，同源性不受影响）。
- **模型输出本身以 `/命令 ` 开头时**，结果刚刚生成就被误判为「已改」（一侧剥前缀、一侧没剥）。
- **「重新优化」可能静默带上遗留的澄清问答**：极端路径下（上一段从零会话被放弃后）会把旧问答并回全局记录。现已彻底隔离（作废路径清空暂存），并补了**请求载荷级**的测试断言。
- 副键撤回时的回退点判定改为「本轮身份」对齐，避免**草稿文本恰好与旧轮相同**时误弹掉一段仍然有效的记忆链。

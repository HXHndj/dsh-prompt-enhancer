# v4.2.4 — 忙碌态三连修：圆环光学居中 + 悬停底色红化 + 耗时胶囊 `[00:08]`

> 输入框工具行「优化进行中」这一态的完整打磨：修掉你截图指出的**圆环看起来偏高**与**悬停变「取消」时底色却转灰**两个缺陷，并按你拍板的预设①新增**纯展示耗时胶囊**（主键左侧、`mm:ss`、次级灰、点击穿透）。RPC 面 24 条不变、配置 schema 与记忆链结构零改动、**无宿主行为变更**（纯客户端呈现层 + 一个本地秒表）。

## 🎯 修复

- **圆环光学居中：不是圆环偏，是文字偏低 1.5px**。实测（Chromium 字体度量 + 隔离实例读数）：15px 圆环（11px 内容 + 2×2px 描边）由容器 `align-items:center` 居中，落点恰在胶囊纵向中心（`ringCy − btnCy = 0.00px`）；偏低的是**文字**——13px/600 中文（DengXian 栈）行盒 20px 时字体 natural ascent 14 / descent 3，墨迹中心比行盒中心低 **1.5px**（`inkCy − btnCy = +1.50px`），于是环−墨迹偏差 **−1.5px**，视觉上就读作「圆环偏高、未居中」。修法：忙碌态状态文字整体上移 1.5px（`.dsh-enh-btn-busy .dsh-enh-status{position:relative;top:-1.5px}`）——纯绘制位移，不改布局、不改胶囊宽度，绝对定位的「取消」覆盖层同步跟随；圆环几何与 flex 居中一律不动（对照候选「环下移 1.5px」会让整块内容低于胶囊中心，未取）。
- **悬停底色：中性灰 → 红**。旧行为是鼠标移上去文案变「取消」（红字）、底色却被通用规则 `.dsh-enh-btn:hover:not(:disabled)` 覆盖成中性灰，语义脱节。现新增 `.dsh-enh-btn-busy:hover:not(:disabled){background: color-mix(state-error-primary 10%)}`：静止态警示黄 6% → 悬停红 10%（既换色相又略加深）。该规则与通用 hover 规则**同权重 0-3-0**，靠**源码顺序靠后**取胜（单测锁死顺序，防回归）。

## ✨ 新增：忙碌态耗时胶囊 `[00:08]`

按你拍板的预设①落地：主键**左侧**一枚独立淡底小胶囊（位置对应你图三的红框），格式 `mm:ss`、次级灰中性配色、1 秒一跳实时累加。

- **纯展示、零交互风险**：`aria-hidden`（与既有 `.dsh-enh-status` 同口径，语义由主键 `aria-label` 承担）+ `pointer-events:none`（点击穿透 ⇒ 既不可点，也**绝不可能误触主键的「取消」**）+ `user-select:none` + 无 `tabIndex`。
- **不进按钮内**：作为主键左侧的**兄弟节点**渲染 ⇒ `.dsh-enh-split` 子元素顺序扩为 `[aux, timer, main, EnhanceMenu]`（null 槽由 React 忽略）。副键只在 result/idle、耗时胶囊只在 enhancing ⇒ 二者恒不同时出现，**非忙碌态结构契约不变**。
- **数据源 = 本地秒表**：进入 enhancing 起算 + `timerSvc.interval` 每秒一跳。刻意**不复用** `enhance/progress` 的 `elapsedMs`——那是 500ms 轮询回来的 host 值，轮询失败时会长时间冻结，而耗时是纯展示信息、不该随网络抖动失真。
- **格式**：`00:08` / `01:05`，超过 99 分钟继续按分钟增长（`128:50`）；`tabular-nums` + `tnum` 等宽数字 ⇒ 逐秒进位不抖动；`min-width:48px` 容下 `mm:ss` 满宽。
- **形态与节奏**：28px 高、与主键同高同轴；全圆角 + `corner-shape:round`（退出宿主全局超椭圆，与副键同款做法）；`label-secondary` 6% 淡底（与 `.dsh-enh-btn-redo` 同一中性底配方；不用 hover 专用 token 当静止底）；与主键 2px 间隙（与副键同款节奏）。

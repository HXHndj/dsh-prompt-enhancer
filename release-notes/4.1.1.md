# v4.1.1 — ✨ 只表示记忆流开关（空输入态零专属样式）+ 专家档记忆行观感修正

> 纯前端 UI 语义修正：把「✨ 的亮灭」单一职责化为**记忆流开关指示**，并修正专家档下记忆行「该灰的没灰、不该灰的灰了」的问题。**无行为变更**——RPC 面、配置 schema、记忆链数据流逐字未动，升级后无需重新配置。

## 🎨 界面（输入框增强按钮）

- **✨ 只表示记忆流开关**：此前空输入也会把 ✨ 压灰，于是「空输入 + 记忆流开」会被误读成「记忆流关」；**专家档强制开启记忆时更是自相矛盾**（✨ 显示关、而菜单里的开关是开）。现在 ✨ 的饱和度只由记忆流决定——轻量 / 标准档跟随你自己的开关，专家档恒彩色；切档即时刷新，且专家档不覆盖你原来的开关状态（切回自动恢复）。
- **空输入态零专属样式**：空输入不再有专门的置灰样式与类名；「暂无可优化内容」不再借用 ✨ 表意，改由点击行为本身承担（空输入点击 = 打开增强设置卡，v3.5.7 行为不变）。模式短标签在有字 / 无字两态下**逐字同色**。

## 🎨 界面（▾ 增强设置菜单）

- **专家档记忆行：标签正常色，仅开关控件置灰**：记忆流标签不再跟着整行一起变暗；置灰只落在开关控件上（与宿主原生 Switch 的禁用观感一致），开关仍保持「开」的位置与读数。设置页与 ▾ 菜单两处入口口径统一。
- 轻量 / 标准档下的记忆行与开关**完全保持原状**。

## 🔧 兼容性

- **无行为变更**：不涉及 RPC（线上 24 条方法不变）、配置 schema、模板与记忆链数据；浏览器内的既有配置原样保留。
- 组标题、字段文案与提示文案（含中英双语）逐字未动。

## ✅ 本次实测

- 构建与产物漂移校验（`build-host --check` / `build-client --check`）通过；四门禁 `npm run gate`：**通过 30 · 冲突 0**；全量单测 **245 / 245 / 0**。
- **隔离临时实例真值表逐格实测**（空 / 有字 × 记忆开 / 关 / 专家强制开，共 6 格，以草稿内容实测确认而非推断）——✨ 与 ▾ 菜单记忆流开关读数**逐格一致**，且同档位下空 / 有字两态 ✨ 完全相同。

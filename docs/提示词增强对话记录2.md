DS：一、落地后的协议

**模型 → 插件**（仅专家档，除 JSON 外无正文；不得在正文里反问用户）：

json



```
{"clarify": true, "questions": [
  {"kind": "gap",       "q": "「它」具体指哪个函数？"},
  {"kind": "gap",       "q": "期望输出格式？", "options": ["Markdown", "纯文本"]},
  {"kind": "ambiguity", "q": "调用处如何处理？", "options": ["同步改所有调用处", "保持接口不变", "仅提醒"]}
]}
```

- 题数 **1–3**（一个或多个，超出截断）；`kind` 缺省 `ambiguity`；**内容/选项/类型全部由模型判断生成**（实测同一草稿不同轮次产出 1 题或 2 题，正是模型在决定）。
- **gap＝补信息**：可不给选项（自由输入），也可给 0–4 个建议选项；卡片上永远有「**保留原句**」这一行。
- **ambiguity＝消歧**：必须 2–4 个选项 + 自定义输入。

**插件 → 模型**：`clarifyAnswers: [{q, a, via}]`，`via ∈ {option, custom, keep}`；`keep` 表示该点保留原句（`a=""`）。点「跳过直接优化」＝ `skip:true` **且**为每题附一条 keep 条目。

## 二、真实渲染核验（不是静态推演）

| 场景            | 实测结果                                                     |
| --------------- | ------------------------------------------------------------ |
| 两类问题同卡    | gap 题（标签「补充信息」+「保留原句」行 + 输入框）与 ambiguity 题（标签「澄清歧义」+ 3 选项 + 输入框）共存，形态沿用原生 ask-user 配方 |
| 保留原句 → 提交 | 选中后 `aria-checked=true`、✓ 显示、提交由禁用变可用；提交后卡片消失、**终稿＝原句未改**（歧义点保持原文原样，不替你选边） |
| 跳过直接优化    | 卡片消失、**终稿＝原句未改**（全部按保守策略处理）           |
| 副产物验证      | 已选「保留原句」的点，**下一轮模型不再追问**（实测第二次优化直接出终稿）——这正是把 keep 写进记忆链的预期效果 |
